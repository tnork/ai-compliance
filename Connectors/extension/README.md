# AI Compliance Capture — browser extension (v0.1, MV3)

Real-time capture of AI prompts/outputs on **cloud web UIs** (ChatGPT, Claude, Grok, Gemini, Copilot) for **any account tier** — personal or enterprise. Complements the server-side enterprise Compliance-API connector (`web/lib/connectors/`), which covers firms that have enterprise seats. Together they answer "log every prompt/output automatically, personal and enterprise accounts."

> **Durability hardening (2026-07-12, v0.1.3, Codex P1s):** the buffer now has a SINGLE WRITER - `content.js` is a stateless emitter (hash + `sendMessage`); every mutation (append from any tab, sync ack-filter, retention strip) runs through one serialized queue in `background.js`, so a sync can no longer clobber an event a tab just captured. Eviction is GONE entirely: the manifest requests `unlimitedStorage`, unacked events are never dropped and retained text is never degraded (per-event text is clipped to the 100k server bound at append; a 5,000+ backlog logs a loud warning). The local hash chain covers a text-free projection, so the one policy-mandated strip (firm turns retention off) can't break it. Acks fail closed: a 2xx without a valid `accepted` array keeps the whole batch (same fix in the desktop logger). Events also carry `surface` (browser) + `os` telemetry (migration 0029).

> **Sync latency fix (2026-07-12, v0.1.2):** sync was periodic-only (~7 min), so a user who asked a question and closed the browser left the event on disk until ~7 min into the NEXT session. Now event-driven: capture → 30s debounce alarm → upload, plus a startup flush. The 7-min alarm remains as the retry backstop. Durability was never at risk (events persist locally until server-acked) - this closes the latency gap.

> **Parser fix (2026-07-11, v0.1.1):** ChatGPT's compact JSON-patch protocol batches ops as `{o:"patch", v:[...]}` and opens messages via object-valued `add` ops — the old parser dropped both, losing the answer's head + mid-stream chunks (found in the founder's Edge test). `extractOutput` is now a stateful per-message accumulator (batched patches recursed, thoughts messages skipped, replaces authoritative); 7/7 synthetic-stream unit tests incl. Claude/Grok regression guards.

> **Parser status (2026-07-10):** **ChatGPT, Claude, Grok, and Gemini are PROVEN against live traffic** on real accounts. **Copilot is wired but UNPROVEN** (no test account yet — keep it "coming soon" in customer copy). Provider payloads drift (the documented "maintenance treadmill"); to re-tune a site: open it, run `localStorage.aicompliance_debug='1'` in its console, reload, send a prompt, and read the `[AI Compliance]` lines (matched URL + parsed prompt/output). Transport map + parser notes live in the `web-ai-chat-capture-transports-and-parsers` skill.

## Browser support

- **Chrome** — proven live (2026-07-10).
- **Edge — PROVEN LIVE (2026-07-11, founder):** full round trip on a real account — capture, sync, encrypted content retention, hash-verified review. **Brave, Arc, Opera, Vivaldi** (same Chromium engine) run the identical unpacked extension; one-time smoke test each before claiming in marketing. Edge can also install from the Chrome Web Store.
- **Firefox 140+** — ported (dual `background` keys: Chrome runs the `service_worker`, Firefox runs `scripts` as an event page — this is [MDN's recommended cross-browser MV3 pattern](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background); Chrome 121+ ignores `scripts`, Firefox 121+ ignores `service_worker`. A 2026-07-11 Codex review flagged dual keys as non-portable — that's pre-Chrome-121 behavior, refuted against MDN; if a store submission ever does reject it, the fallback is stripping the other browser's key at package time. `world: "MAIN"` content scripts are supported since Firefox 128). **PROVEN LIVE 2026-07-12 (founder):** full round trip on **both claude.ai and chatgpt.com** - inject -> capture -> sync -> record. Firefox is out of beta. Three Firefox-specific behaviors:
  - Firefox MV3 treats `host_permissions` as **optional** — nothing is granted at install, so content scripts don't inject until the user clicks **"Allow access to AI sites"** in the popup (the popup shows a warning until granted; Chrome auto-hides it because Chrome grants at install).
  - **After granting, RELOAD THE EXTENSION** (`about:debugging` → Reload). Firefox does not activate manifest-declared content scripts for origins granted at runtime until the extension reloads; Chrome injects on the next page load. Symptom if you skip it: zero `[AI Compliance]` debug lines and `window.fetch.toString()` shows native code - it looks exactly like a broken port.
  - AMO (Firefox add-on store) submission requires the `data_collection_permissions` declaration already in the manifest (`websiteActivity` + `websiteContent` — honest: metadata/hashes always transmit; conversation text transmits only when the firm turns on content retention).
- **Safari** — not supported (requires an Xcode-wrapped Safari Web Extension + App Store distribution; deliberately deferred). A firm's policy should name unsupported browsers as excluded surfaces; the coverage dashboard shows the gap.

Chrome shows a benign "Unrecognized manifest key 'browser_specific_settings'" warning on load-unpacked — expected; the key is Firefox-only and Chrome ignores it.

## How it works
- `inject.js` (MAIN world, `document_start`) monkey-patches BOTH `window.fetch` and `XMLHttpRequest`, tees the AI app's own conversation traffic — one branch to the page (UX unbroken), one parsed for the assistant output; the prompt is read from the request body (Gemini: from the `batchexecute` XHR *response*). **Never DOM scraping** — it tees the app's real network calls.
- `content.js` (ISOLATED world) receives events via `postMessage`, hashes content locally (raw text is kept only when the firm's content-retention setting is on), hash-chains events (tamper-evidence), buffers to `chrome.storage.local` (sandboxed per-extension).
- `background.js` (service worker in Chrome; event page in Firefox) drains the buffer to `POST /api/ingest`, authed with the user's AI Compliance access token. **Sync triggers (v0.1.2), fastest first:** ~30s after each captured turn (one-shot debounce alarm - 30s is the MV3 alarm minimum - re-armed per capture so a Q&A burst uploads as one batch) · on browser startup (flushes events buffered when the browser was last closed) · a 7-min periodic alarm as the retry backstop · the popup's "Sync now". Events persist in `chrome.storage.local` until the server acks them, so closing the tab/browser/laptop delays the upload but never loses the record. `/api/ingest` attributes events to the signed-in user and lands them as **reviewed=false** (they surface as §10.22 review gaps until a human reviews them).
- `auth.js` (shared, v0.2) — connect-once auth. A one-time **connect code** from the app's Connections page (a Supabase magic-link token_hash + the env's public URLs/keys) is redeemed for the extension's **own session** (separate refresh-token family from the browser tab's login), stored in `chrome.storage.local`, and **self-refreshed forever** — in production there is no hourly re-paste. Chrome loads it via `importScripts` in the service worker; Firefox lists it before `background.js` in `background.scripts`; the popup loads it via `<script>` (it needs `parseConnectCode` so the localhost permission prompt can ride the user's click). Only definitive auth rejections (400/401/403 on refresh) kill the session; 429/5xx/offline are retried. Connect codes are allowlist-validated (app origin + `*.supabase.co`) so a crafted code can't point capture at an arbitrary host.
- `popup.html/js` — connect (paste a connect code; legacy raw-token flow under Advanced), "Sync now", disconnect, and the site-access grant (Firefox).

## Status / honest limits
- **Full-fidelity capture (verified 2026-07-11):** the prompt and the complete answer are captured verbatim. The only bound - identical across the extension, the desktop logger, and `/api/ingest` - is 100,000 chars per field (~40 pages; no real chat turn approaches it). Anything shorter than that in a record is a parser bug, not a policy - report it.
- **v0.1.** ChatGPT/Claude/Grok/Gemini proven live on Chrome (+ Edge); **Firefox proven on Claude + ChatGPT (2026-07-12)**; every other browser/provider combination needs its own live validation before it's claimed anywhere customer-facing.
- **ChatGPT on Firefox: proven (2026-07-12).** A first pass misread ChatGPT's speculative `/f/conversation/**prepare**` prefetches (no message; response is only a `conduit_token`) as a new WebSocket transport. It wasn't - the real `/backend-api/f/conversation` turn streams over fetch/SSE and captures full-fidelity once the abort-salvage fix stopped dropping it. `isTurn` now **excludes `/prepare`** so those prefetches don't log misleading "MATCHED TURN -> NULL" lines. The DEBUG WS logger (send + receive frames) remains for the day a provider genuinely moves a turn onto a socket.
- **Stream aborts are salvaged (fixed 2026-07-12).** We read a `clone()` of the response stream in the background; Firefox propagates the page's own `AbortController` cleanup (fired *after* the page finished reading) into that clone, so the reader throws `AbortError` even though every byte already arrived. The reader now keeps its buffer **outside** the try block and parses whatever accumulated on any interruption - dropping it lost entire answers on Firefox. A genuine mid-stream abort (user hits "stop generating") now yields exactly what the model produced.
- **At-rest encryption:** the browser buffer relies on the browser's per-extension storage sandbox + the local hash chain. Strong OS-keystore AES encryption is the **desktop logger's** domain (`desktop/`).
- **Auth is v0.2 — connect once, stays connected.** Pair with a one-time connect code (app → Connections); the extension self-refreshes its own session from then on. The legacy paste-an-access-token flow (~1h lifetime) remains under the popup's Advanced section for dev/testing. Note: `chrome.storage.local` is not OS-keychain encrypted — the stored session has the same at-rest posture as the legacy token (browser profile sandbox).
- Desktop apps (Claude Desktop/Code, Codex) and local LLMs are covered by the **desktop logger** (`desktop/`), not this extension. Mobile is covered via the enterprise Compliance API, not here.

## Load for testing
There's no compiled binary — the source files in this folder ARE the extension. A packaged
zip (for Chrome Web Store / Firefox AMO upload, or sending to a tester) is built with
`zip -r aicompliance-extension.zip .` from here.
- **Chrome / Edge / Brave (Chromium):** `chrome://extensions` (Edge: `edge://extensions`) → Developer mode → Load unpacked → select this `Connectors/extension/` folder.
- **Firefox:** `about:debugging#/runtime/this-firefox` → Load Temporary Add-on → select **`manifest.json`** (a file *inside* the folder - Firefox never accepts the folder itself; and note `about:addons` → "Install Add-on From File" only takes a **signed** .xpi, which is why `manifest.json` looks unselectable there). Then open the popup, click **"Allow access to AI sites"**, and **reload the extension** (both required - see Browser support above). A temporary add-on is removed when Firefox fully restarts.

Open the popup, paste a **connect code** (from the app under **Connections**), then use an AI site and watch events arrive under **Review records** in the app — the extension stays connected on its own from then on.
